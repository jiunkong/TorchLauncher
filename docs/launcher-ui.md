# 런처 UI 재작성 명세

2026-10-22 사용자와 시안으로 확정한 내용이다. 시안 소스는 [`docs/design/launcher/`](design/launcher/README.md). 기능 계약(IPC, 인증, 설치, 동기화, 복구)은 바꾸지 않고 **화면과 흐름을 재작성**한다. 계약 변경이 필요하면 #0에 요청한다.

## 단계

| 단계 | 범위 | 상태 |
| --- | --- | --- |
| L1 / L1b | 디자인 토큰, 앱 셸(접이식 메뉴), 시작 애니메이션, 홈과 상태별 표현, 게임 종료 확인, 한글 글꼴(Pretendard) 번들, 텍스트 선택·끌기 차단, 제품 상태의 게임 정보·시작 시각 | 통합 완료 |
| L2b | 세션·복구 자동화와 로그 출처 구분(메인 프로세스·상태 계약) | 통합 완료 |
| L2a | 내 모드 · 설정 · 로그 페이지, 앱 안 삭제/복구 확인 창(OS 대화상자 없음), 실제 순서의 진행 패널 | 통합 완료 (`docs/handoffs/LAUNCHER-UI-L2A.md`) |
| L3 브랜딩 | 프로파일 앱 이름·동봉/캐시 아이콘·배경, torchpack 변경 이미지 비차단 갱신 | 구현·통합 검사 완료, Windows/실배포 검증 대기 |
| L3 스킨 | 프로필 스킨 얼굴·모자, 캐시/로그아웃 정리/첫 글자 fallback | 구현·통합 검사 완료, Windows·실계정 미검증 |

단계는 렌더러 파일을 공유하므로 직렬로 진행한다. 각 단계는 별도 브랜치, 별도 인계 문서로 통합한다.

## 확정된 디자인 결정

- **테마:** 어두운 테마 하나. 색은 `launcher.css`의 `.win` 토큰(`--bg`, `--panel`, `--red` 등)을 그대로 쓴다. 브랜드 아이템은 레드스톤 토치(`assets/branding/icon.png`, 픽셀 이미지는 `image-rendering: pixelated`).
- **언어:** 한국어 기준. 모든 사용자용 문구는 기존 i18n 기반(`@torchlauncher/core/i18n`, `apps/launcher/src/renderer/src/i18n`)의 사전에 넣고 컴포넌트에 직접 쓰지 않는다. 영어 사전은 이번 범위에서 채우지 않는다(키 parity 테스트는 유지, 영어 값은 임시로 한국어 값이나 빈 처리 정책을 기존 기반에 맞춘다). 서버 이름·경로·파일 이름·원본 로그는 번역하지 않는다.
- **창:** 높이 36px의 어두운 제목 표시줄(`--bg-deep`)을 직접 그린다. 최소화·최대화·닫기는 `titleBarOverlay`로 OS 네이티브 컨트롤을 그대로 쓰고, 아이콘과 창 제목은 표시줄 왼쪽에 둔다. 표시줄 전체가 창을 끄는 드래그 영역이며 본문은 그 아래에서 시작한다. 좁은 창에서도 표시줄이 문서 가로 스크롤을 만들지 않도록 내용 폭을 창 폭 안으로 제한한다.
- **글꼴:** 본문은 시스템 글꼴 스택(`'Segoe UI', 'Malgun Gothic', 'Noto Sans KR', system-ui, sans-serif`). 워드마크만 Pixelify Sans(OFL) woff2를 앱 자산으로 번들하고 라이선스 고지를 함께 둔다. 외부 네트워크로 글꼴을 받지 않는다.
- **시작 애니메이션:** 항상 TorchLauncher 로고와 이름(운영자 지정과 무관). 기본 1.5~2.5초 재생, 앱 로딩이 더 오래 걸리면 로딩이 끝날 때까지 토치가 켜진 채 대기하다가 마무리 애니메이션 후 홈으로 넘어간다. 로딩 바는 얇고 단순하게. "서버 전용 클라이언트" 같은 부제는 쓰지 않는다. `prefers-reduced-motion`이면 움직임을 줄이거나 끈다. 재생 중에도 로딩 실패를 가리지 않는다(오류는 홈에서 표시).
- **메뉴:** 왼쪽 세로 메뉴. 기본은 닫힘(아이콘만, 폭 64px), 햄버거로 열면 폭 232px에 이름이 보인다. 항목은 플레이 · 내 모드 · 설정 · 로그. 열린 메뉴 맨 위에 운영자 아이콘과 서버 이름(주소는 표시하지 않음), 맨 아래에 계정 영역(아바타, 닉네임, 로그아웃 아이콘 버튼)이 있다. 닫힌 메뉴는 아바타만 보인다. 상태는 시작할 때 항상 닫힘.
- **홈:** 운영자 배경이 오른쪽 영역을 가득 채운다(없으면 기본 배경). 보이는 정보는 서버 온라인 여부·접속 인원 한 줄, 서버 이름, Minecraft 버전과 로더 한 줄, 플레이 버튼뿐이다. 서버 주소는 표시하지 않는다. 서버 파일 재확인 버튼은 없다(플레이 시 항상 최신 확인·동기화가 먼저 수행되고 실패하면 실행을 막는다).
- **홈 상태:** (1) 로그인 필요: 버튼이 "Microsoft 계정으로 로그인". (2) 설치/동기화: 상단 패널에 현재 활동·완료 개수·불확정 진행 바·단계 칩, 버튼은 "설치하는 중…"과 "취소". (3) 게임 실행 중: 상태 "게임 실행 중 · 경과 시간", 버튼이 "게임 종료"로 바뀌고 누르면 확인 창. (4) 오류: 호박색 패널(원인), 버튼은 "다시 시도", "로그 보기" 링크. 전체 개수를 모르는 단계에 임의 비율을 만들지 않는다.
- **페이지:** 내 모드(내 모드 목록 / 서버 관리 모드 읽기 전용 목록 / 등록되지 않은 파일), 설정(런처 종료 설정 / 리소스팩 순서 / 서버 데이터 용량과 삭제), 로그(필터 탭 전체·런처·게임, 복사, 폴더 열기). "문제 해결" 페이지와 그 안의 계정 세션 카드·복구 카드는 없앤다.
- **확인 창:** 서버 데이터 삭제(대상·용량·삭제되는 것/안 되는 것), 이전 실행 확인(자동 복구가 불가능할 때만, 체크해야 버튼 활성), 게임 종료("게임을 종료할까요? 저장되지 않은 진행 상황이 사라질 수 있습니다.").
- **계정:** 닉네임만 표시(이메일·MS 계정명 없음). 로그아웃은 열린 메뉴 맨 아래. 프로필 이미지는 L3의 스킨 얼굴, 그 전까지 닉네임 첫 글자 아바타.
- **문구 정리(사용자 피드백):** 시안에서 제거한 설명 문구를 다시 넣지 않는다. 시안의 한국어 문구가 최종 문구다.

## 동작 변경 (L2에서 구현)
- 계정 세션: 시작할 때 자동 복원, 플레이 흐름에서 필요할 때 갱신. 수동 "세션 확인" UI 없음.
- 복구: 주인과 자식 프로세스 종료가 확인된 stale 상태(GAME-05의 `stale-verified`)는 시작 시와 플레이 시도 시 **자동 복구**하고 로그에만 남긴다. `uncertain`일 때만 "이전 실행 확인" 창을 띄운다.

## 지켜야 할 제약
- 서버 프로파일은 하나만 있다. 서버 선택·추가·주소 입력 UI를 만들지 않는다.
- 게임 실행은 월드 접속 완료를 뜻하지 않는다. 서버 상태의 미조회/실패/온라인/오프라인을 구분한다.
- 모드·팩 조회의 미조회/빈 목록/오류를 구분하고 진행 이벤트가 사용자 초안을 덮어쓰지 않게 한다(기존 동작 유지).
- 삭제·복구 확인, IPC 검증, 직렬화와 중복 실행 방지, 최신 배포 동기화 후 실행 경계, 취소와 종료 동작을 유지한다.
- "게임 실행 후 런처 종료" 설정(기본 off)과 게임 생존 중 잠금 유지를 유지한다.
- 준비되지 않은 기능에 가짜 성공 상태를 만들지 않는다. 시안에 있어도 코어가 없는 기능은 L2/L3 범위로 둔다.
- 접근성: 실제 `button`/`a`/`input`+`label`, 아이콘 전용 버튼의 `aria-label`, 키보드 포커스 표시, 글자 대비 4.5:1, 서로 구분해야 하는 색은 밝기도 다르게. 좁은 창(최소 760px)에서 깨지지 않게.
- 새 의존성, 루트 설정, lockfile, 공용 IPC 계약, Studio 앱 변경은 #0과 조정한다.

## 검증
`pnpm check`, `node scripts/smoke.mjs`(런처 부분), `node apps/launcher/scripts/renderer-functional-smoke.mjs`. 화면은 760px와 1100px에서 확인하고 스크린샷으로 시안과 비교한다(`.cache/smoke/`, 커밋하지 않음). Windows 실행은 #0이 사용자에게 요청한다. 시안과 다른 부분이나 구현 불가능한 부분은 인계 문서에 이유와 함께 적는다.

## 구현 중 확정·변경된 사항 (L1/L1b)
- 한글 본문 글꼴은 Pretendard Variable(OFL, 약 2 MB)을 번들한다. 워드마크는 Pixelify Sans. 라이선스 고지는 패키지(`font-licenses-NOTICE.txt`)에 포함된다.
- 텍스트 선택과 끌기를 전역에서 막고(`user-select: none`, 이미지·링크 끌기 방지, 창으로의 드롭 차단), 입력·로그·`.selectable` 영역만 선택 가능하다. 의도된 드롭 영역이 생기면(예: 모드 .jar 끌어다 놓기) 그 영역만 예외로 허용한다.
- `ProductState.game`은 서버 구성의 선택 `game` 표시 hint와 이후 검증된 배포 인덱스로 채운다. 현재 Studio 내보내기는 game을 포함한다. 실제 실행 기준은 서명 검증된 최신 인덱스다.
- `runningSince`(게임 시작 시각)가 상태에 추가되어 경과 시간이 렌더러 재시작에도 정확하다.

## 설치·확인 진행 표시 결정 (2026-10-22)
- 플레이할 때마다 게임 파일 전체(에셋 약 4,000개, 라이브러리, 게임 본체, Java 런타임)를 해시로 확인하는 현재 방식을 **그대로 유지한다.** 시간이 길지 않으므로 빠른 경로(크기·시각 기록 기반 생략)는 만들지 않는다.
- 실제 처리 순서는 계획 → 게임 파일 풀(게임 본체·라이브러리·에셋·로깅 설정, 이어서 Java 런타임 파일, 동시 6개) → 로더 설치 → 서버 파일 동기화이다. 현재 홈의 단계 칩(Java → 게임 → 라이브러리 → 에셋 …)은 실제 순서와 다르고 병렬 처리로 항목이 번갈아 깜빡인다.
- L2에서 진행 패널을 **실제 단계 순서의 요약**으로 바꾼다: 정보 확인 → 게임 파일 확인·받기 → 로더 설치 → 서버 파일 동기화. 게임 파일 단계는 총 개수가 계획 후 확정되므로 "완료 / 전체"와 진행 바(비율)를 보여 준다. 개별 파일 이름 갱신은 제거하거나 느리게 한다. 서버 파일 동기화 단계는 총 개수가 불확정이므로 비율을 만들지 않는다.

## L2a 후속 및 잔여 항목 (#0 기록 2026-10-23)
- 구현: 읽기 전용 인자 없는 IPC `open-logs`(게임 실행 중에도 로그 폴더 열기).
  서버 데이터 루트는 별도 `serverDataRoot` 상태로 전달해 삭제 미리보기 없이 설정의 "위치"를 표시한다.
  설정의 긴 위치 경로는 한 줄 말줄임으로 표시하며 전체 문자열은 title/선택 복사에 보존한다.
  삭제 확인 창의 전체 경로 줄바꿈 표시는 유지한다.
- 구현: 별도 `remove-unregistered` 명령으로 코어 `removeUnregistered`를 호출한다.
  미등록 일반 파일도 지원하고 앱 안 대상 확인 후 삭제한다. 운영자/등록 파일과 실행 중 잠금 경계는 유지한다.
- 모드 파일 크기, 팩 표시 이름, 로그 시각은 상태에 없어 생략됨. 필요하면 상태 확장.
- 서버 데이터 삭제·이전 실행 복구는 OS 대화상자 없이 앱 안 창과 코어 확인 토큰으로만 확인한다(사용자 결정 2026-10-23).

## 메모리 설정·표시 후속 결정 (2026-10-23)

- 설정에 개인 Xmx/Xms 입력을 추가했다. 기본 최대 2GB·초기 미지정, 일반 숫자 직접 입력을 제공한다.
  숫자 스피너·0.5GB 권장 단위 안내·메모리 저장 성공 문구는 표시하지 않는다. 초기값을 비우면 Java 기본값을 사용한다.
- 좌우 드래그 조절은 사용자 피드백으로 제거했다. 값을 입력하고 저장을 눌러야 반영한다.
  현재 실행 중인 게임에는 영향을 주지 않고 다음 실행에 적용한다.
  범위/관계 검증·75% RAM 경고·저장 실패 안내는 유지한다. 전역 텍스트 선택·끌기 차단은 바꾸지 않는다.
- 플레이 탭에 ‘최근 결과’를 표시하지 않는다. 내부 결과/로그·오류·진행 상태·복구 안내는 유지한다.

## L3 브랜딩 통합 (2026-10-23)

[혼합 전달 명세](operator-branding-hybrid.md)대로 초기 이미지는 서버 JSON 옆에 동봉하고,
변경 이미지는 서명된 torchpack v1.2 역할별 payload로 갱신한다. 기존 이미지 유지 후 검증·디코드 성공 때
220ms 교차 페이드, reduced-motion 즉시 전환. 원격 null 제거는 캐시에 보존한다.
창 제목/창 아이콘/메뉴 이름·아이콘/홈 배경에만 반영하며 시작 TorchLauncher 로고와 exe는 고정이다.
Studio 기능 API는 통합했지만 설정 화면은 사용자 요청으로 변경하지 않았다.
main 전체 검사1051/9skip, 실제 Electron 두 branding smoke·기존 앱 smoke 성공.
새 브랜딩 Windows/실배포 검증은 대기다.
