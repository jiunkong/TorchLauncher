# UI-PROD-01 — 기능 흐름 우선

2026-10-22 사용자 승인: 프로덕션 UI 작업을 시작하되 예쁘게 꾸미는 작업은 하지 않는다.
기존 색상/테마/장식은 유지하고 실제 기능의 발견·상태·다음 동작·오류 복구를 우선한다.
#0은 문서/배정/검토/통합만 하고 두 구현 작업자가 앱별로 나눠 작업한다.

## 통합 결과

기능 흐름 단계 통합 완료. Studio `9b8d7b0`와 후속 smoke 수정, 런처 `42b5aef`·`aeff584`·
`95aa7df`를 통합했다. 메인 전체 검사 796개/9 skip 성공 후 renderer 추가 회귀 9개도 성공했다.
두 앱의 root Electron smoke와 각 앱 기능 smoke를 Linux/WSLg에서 확인했다. 자세한 증거는
`docs/progress.md`, `docs/handoffs/UI-PROD-01-{L,S}.md`를 따른다. 새로운 실계정 로그인/게임 실행은
반복하지 않았고 Windows 네이티브 검증과 시각 디자인 고도화는 별도다. 아래는 작업 시 적용한 범위다.

## 런처 — #4 / ui_prod_launcher

`feat/ui-prod-launcher-flow`, agent-4. 독점: `apps/launcher/src/renderer/**`,
`apps/launcher/scripts/**`의 기능 검증 도구, `docs/handoffs/UI-PROD-01-L.md`.

- 기본 화면은 제공된 단일 서버 정보·계정·접속·진행 상태 중심. 서버 선택/추가/주소 입력 금지.
- 계정 없으면 로그인, 준비되면 접속, 준비/실행 중이면 취소/종료 등 현재 가능한 주 동작을 명확히 한다.
  초기 계정 복원/작업 중 중복 클릭과 서로 충돌하는 동작은 막고 main의 검증/직렬화를 유지한다.
- GAME-ACTIVITY-01을 실제 표시: 게임·Java·라이브러리·에셋·로더·서버 모드/팩/설정·기타 파일,
  확인/다운로드/적용 단계, 파일 개수/활성 작업. 알 수 없는 전체 수는 불확정 표시,
  원본 단계 코드/계획 수를 사용자용 완료율로 쓰지 않는다. 기본 화면에 원본 경로를 나열하지 않는다.
- 수동 세션 갱신·복구·상세 로그는 설정/문제 해결로 옮기며 숨겨서 기능을 없애지 않는다.
  계정 만료·네트워크·설정 문제·취소·프로세스 종료를 구분하고 안전한 재시도/이동을 제공한다.
  게임 실행 상태를 서버 접속 완료로 단정하지 않는다.
- 모드·설정 페이지에서 필요한 조회를 자연스럽게 수행하고 미조회/빈 목록/실패를 구분한다.
  사용자 입력 초안은 다른 진행 이벤트로 덮어쓰지 않고, destructive 동작의 확인 절차를 유지한다.
- 순수 상태/문구/주 동작 분기 테스트와 Electron 기능 검사로 확인한다. 테스트를 위한 제품 backdoor는 만들지 않는다.

## Studio — #1 / ui_prod_studio

`feat/ui-prod-studio-flow`, agent-1. 독점: `apps/admin/**`, `scripts/smoke.mjs`,
`docs/handoffs/UI-PROD-01-S.md`. 공통 smoke를 수정하는 구현자는 #1 한 명이다.

- 프로젝트 생성/열기→서버·게임 환경→소스/파일/정책→배포 생성→직접 업로드/URL 검사→내보내기 흐름을 만든다.
  이름만 있는 안내 카드 대신 다음 단계로 이동하거나 실제 동작을 실행할 수 있게 한다.
- 필요한 조건/누락값/유효성 오류를 관련 필드와 동작 옆에 표시하고 다음 할 일을 안내한다.
  프로젝트/소스 폴더/배포 URL의 준비 상태를 구분한다. 완료/검증 성공은 실제 결과가 있을 때만 표시한다.
- 미저장 초안·저장 중·취소·실패 상태를 구분한다. 중복 동작을 막고 잘못된 입력이 있어도 새로 열기/취소/수정은 가능하게 한다.
  진행 표시는 실제 작업 종류에 맞게 하고 전체 수를 모르면 임의 비율/의미 없는 KiB를 표시하지 않는다.
- 폴더 내보내기·소스 재선택 등 현재 제약은 해당 단계에만 명확히 안내한다. 이미지/단일 파일 패키징을 구현한 것처럼 표시하지 않는다.
- 실제 파일 저장·생성·재열기·필수 조건·취소/실패/재시도 검증을 갱신하고 두 앱 smoke와 연동한다.

## 범위와 완료 기준

새 의존성/이미지/애니메이션/디자인 시스템은 추가하지 않는다. 공통 manifest/lockfile/core/기존 IPC 변경은
먼저 #0과 조정한다. Studio의 기존 app-local 타입/상태를 개선할 필요가 있으면 #1이 소유한다.
두 앱은 기존 기능을 보존하고 키보드로 주 작업을 수행할 수 있어야 한다.
작업자는 기존 테스트와 760/1100px smoke의 변경을 서로 알리고 API/화면 계약을 맞춘다.
통합 후 #0이 전체 검사와 두 앱 기능 smoke를 수행한다. 새 실계정 로그인/서버 접속은 필요할 때만 사용자에게 요청한다.
시각 디자인 고도화와 아직 없는 Studio 이미지/설정 편의 기능은 이번 완료 범위가 아니다.
