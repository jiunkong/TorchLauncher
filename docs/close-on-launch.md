# LAUNCH-EXIT-01 — 게임 실행 후 런처 자동 종료

2026-10-22 사용자 승인. UI 개편은 미루고 이 기능만 추가한다. #0은 배정/검토/통합을 맡고
#3 구현 작업자 한 명이 코어와 앱을 함께 소유한다.

## 동작

- 개인 런처 설정 `closeOnLaunch`, 기본 false. 설정 화면 체크박스로 변경하고 재실행 후에도 유지한다.
- true면 최신 배포 확인/설치/인증/동기화/설정/최종 실행 검사를 모두 통과하고 게임 프로세스를
  안전하게 분리한 뒤 **Electron 런처 프로세스를 종료**한다. 단순 창 숨김이 아니다.
- 게임 시작 실패/취소/인증·동기화 실패에는 자동 종료하지 않는다. 서버 월드 접속 성공을 측정하는 기능은 아니다.
- false면 기존 게임 관리/로그/취소/일반 종료 동작을 유지한다. 최소 설정 UI만 추가하고 시각 디자인은 하지 않는다.

## 프로세스·데이터 경계

Windows에서는 일반 spawn 자식이 Electron 호스트 종료 시 함께 종료되는 것이 기존 실측으로 확인됐다.
분리 실행과 표준 입출력/취소 신호/프로세스 핸들의 정리가 필요하다. 불필요한 상주 Electron은 남기지 않는다.

우선 검토할 설계는 선택된 실행만 detached Java로 시작하고, 실행 중 게임의 PID/시작 식별자를
기존 v2 잠금에 확실히 기록한 뒤 호스트 소유권에서 분리하는 방식이다. 게임 생존 중에는 잠금을
해제하지 않는다. 다음 런처는 살아 있는 자식을 감지해 중복 실행/설치/삭제를 거부하며,
호스트와 게임 모두 종료됐음이 검증된 잠금만 기존 복구 API로 안전하게 회수한다.
PID 재사용·식별 불가·다른 머신·손상 레코드는 기존 보수적 처리/확인 규칙을 유지한다.
자동 복구는 검증된 해당 게임 잠금에 한정하며 미완료 설치/동기화 저널을 무조건 복구하지 않는다.

분리 성공 전에 오류/취소가 발생하면 게임을 정상적으로 종료/회수하고 런처는 유지한다.
정상 종료 루틴이 분리된 게임을 다시 죽이지 않아야 하며, 게임 생존 중 관리 잠금을 풀어서는 안 된다.
위 설계로 기존 안전 경계를 지키기 어렵다면 구현 전에 #0에 구체적인 대안을 보고한다.
