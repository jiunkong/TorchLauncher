# STUDIO-CLOSE-01

Worker agent-1, branch `fix/studio-close-project`.
1. Real `File > Close project`: new command `{action:'closeProject', discard?: boolean}` (shared type; validated like new/open: exact fields, boolean `discard`; trusted frame via the existing handler). No project: harmless no-op; dirty without `discard:true`: `UNSAVED`; BUSY while closing/busy; otherwise main clears project, project name, source, dirty flag, last test result/previews, files/deploy/url check/export/preset/policy/signing and the cached scan state (shared `resetProjectState()` with new/open), and never touches files on disk or the test instance (the account stays signed in). Renderer: the menu item uses the existing unsaved modal (save -> close, 저장 안 함 -> repeat with `discard:true`); the renderer-only hiding and the "replace without asking while hidden" special case are removed.
2. `studio.ts` no longer compares projects with `JSON.stringify`: new `main/canonical.ts` (`canonical()` sorted keys, shared with the project file codec, and `sameContent()`) is used for branding, lastBuild, gameSettings and the whole project in `update`. Tests (`canonical.test.ts`): key order at every depth, nested arrays/objects, array order, missing vs `undefined` optional fields (equal), `null` vs missing (different).
Tests: `test-run.test.ts` (UNSAVED, discard resets everything incl. test-run results and keeps disk files, clean close without discard, no-op, invalid payload/extra fields, BUSY, untrusted sender); Studio smoke: clean close returns to the start screen with `project === null` in main, dirty close asks (cancel keeps, discard goes to start with `dirty:false`).
Not changed: the pending window close request state (`closeAsked`) is untouched; closeProject is refused as BUSY while closing like other commands.
