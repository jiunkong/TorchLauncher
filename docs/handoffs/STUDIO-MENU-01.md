# STUDIO-MENU-01

Worker agent-1, branch `feat/studio-menu-bar`. Renderer + one narrow main command (see Exit).

- `components/MenuBar.tsx` (in-app bar, 32px, always visible incl. the start screen, absolute panels under it with z-index below modals) with role menubar/menu/menuitem/menuitemradio, aria-haspopup/expanded, click to open, hover switches while open, Left/Right between menus, Up/Down/Home/End in a menu, Enter/Space activate, Esc closes and returns focus, outside click closes, Tab closes; disabled items are `aria-disabled` and never activate. `menus.ts` builds File (새 프로젝트 Ctrl+N, 열기… Ctrl+O, 저장 Ctrl+S, 다른 이름으로 저장 Ctrl+Shift+S, 프로젝트 닫기 Ctrl+W, 종료), View (caption `Language / 언어` + 자동 · Auto / 한국어 / English radios using setLocale/followSystem) and Help (정보 -> `AboutDialog`: name, version, platform). One `keydown` listener (removed on unmount) runs the shortcuts; it ignores events while busy, splash, or any `[role=dialog][aria-modal=true]` is open, and never blocks text inputs (Ctrl+S saves from an input). New/open with a dirty project use the existing unsaved modal and `discard:true`.
- Sidebar footer is only the save-state line; the project buttons, language control and version line are gone (start screen keeps its language control). Footer CSS from STUDIO-FIX-01 for the removed controls is left unused.
- **Exit**: a renderer `window.close()` skips main's close handler (the window closed without the unsaved question in my test), so I added the narrowest command: no-payload `{action:'exit'}` (shared type, exact-field validated in `StudioService.request`, trusted frame via the existing handler) which calls `window.close()` in main (`service.onExit`), so the normal close request / unsaved flow applies. Test in `studio.test.ts`.
- **Close project** has no main command, so it hides the project in the renderer (start screen shown, main keeps the project and its dirty flag); creating or opening while hidden replaces it without asking again, since the user already confirmed discarding. Limitation: closing the window afterwards can still ask about unsaved changes of the hidden project; a real `closeProject` command belongs in main.
- i18n ko/en for menu and About keys; `docs/design/studio/README.md` has the decision line.
- Tests: `menus.test.ts` (menu contents, disabled states with/without project and while busy, language radio, shortcut mapping, menubar and About markup); smoke: start-screen menu with disabled items, keyboard open/navigate/Esc, outside click, View > language switch, Help > About (version, one BrowserWindow), New with dirty project asks, Ctrl+S in an input saves, File > Close project, File > Exit asks when dirty, sidebar footer has no buttons, 760x560/900x600 no overflow.
