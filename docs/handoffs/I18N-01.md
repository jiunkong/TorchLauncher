## Delivered

Added a dependency-free shared API at `@torchlauncher/core/i18n`: strict BCP 47 normalization for
`ko`/`en`, ordered automatic preference detection with English fallback, explicit preference handling,
typed catalog/interpolation helpers, placeholder/key parity diagnostics, and a resilient locale store.
Changing preference notifies subscribers even when the resolved language stays the same. The cached
snapshot includes both resolved locale and preference, so `useSyncExternalStore` consumers see
automatic/explicit mode changes. Returning to automatic mode persists `{ mode: "auto" }`.

Each renderer has its own small Korean/English catalog and thin React provider/hook. The launcher and
Studio preference keys are `torchlauncher.launcher.locale-preference` and
`torchlauncher.studio.locale-preference`. Browser storage reads, writes, and getter access are guarded;
corrupt/unavailable storage selects automatic mode, and an in-session choice still works if writes fail.
Language choice remains automatic unless a future UI calls `setLocale`; `useAutomaticLocale` resets it.
OS/browser language changes are sampled at provider creation and when returning to automatic mode; no
live OS language-change listener is installed. Existing screens are untouched and do not consume these
hooks yet.

Catalogs contain shared basic labels and representative launcher/Studio terms only. Interpolation
returns ordinary text strings and does not interpret HTML. Placeholder names must match
`[A-Za-z][\w]*`; parity compares the set of names, so a translated sentence may repeat a name a different
number of times. A missing runtime catalog entry falls back to its key; a missing interpolation value
leaves its `{name}` token visible. There is no plural framework. OS/browser language changes are not
observed live; create the provider again or call `useAutomaticLocale` to resample preferences.

## Usage example

Wrap a future renderer root with its local provider, then consume the hook in components:

```tsx
import { LauncherLocaleProvider, useLauncherLocale } from './i18n/index.js';

function FutureScreen({ player }: { player: string }) {
  const { t, setLocale } = useLauncherLocale();
  return <button onClick={() => setLocale('ko')}>{t('launcher.welcome', { player })}</button>;
}

<LauncherLocaleProvider>
  <FutureScreen />
</LauncherLocaleProvider>
```

For Studio, import `StudioLocaleProvider` and `useStudioLocale` from
`apps/admin/src/renderer/src/i18n/index.tsx` (from within that app, use `./i18n/index.js`). Its store
key is independent from the launcher. The translation function infers permitted keys and interpolation
fields from the English catalog.
