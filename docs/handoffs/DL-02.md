## Implementation

Added `HttpRangeClient` for inclusive byte ranges. It requires `206 Partial Content`, an exact `Content-Range`, validates `Content-Length` when present, and always verifies the received body length. It accepts chunked 206 responses without Content-Length. Responses request identity encoding and reject non-identity `Content-Encoding`. The body is streamed into a range-sized buffer and capped at 64 MiB by default; callers can configure a positive per-request `maxBytes` cap. Unsafe range arithmetic is rejected.

Production URLs and redirects must use HTTPS. Redirects are followed manually with a default limit of five and configurable limit from zero through ten. HTTPS to HTTP downgrades are rejected before following. Cross-origin redirects retain only Range, If-Range, and Accept-Encoding headers. Plain HTTP requires the explicit `HttpRangeClient({ allowInsecureHttp: true })` development/test opt-in.

The client binds its first successful transfer to both the canonical source URL and final URL after redirects, and pins total length, ETag, and Last-Modified. Later calls cannot switch source URLs or effective redirect targets. Requests use `If-Range` when a strong ETag or Last-Modified is available; changes are rejected, including concurrent first-request responses that disagree. Snapshot getters and results return copies of internal metadata. A `200` after a pinned conditional request is reported as a remote resource change.

Transport failures and retryable HTTP statuses (408, 429, and 5xx) retry up to the configured attempt count. Abort stops the transfer and retry wait. Protocol errors, unsupported Range responses, and resource changes fail immediately. `HttpRangeClient.reset()` releases its pinned snapshot for a new transfer. The module entrypoint is `packages/core/src/download/http/index.ts`; package-level exports were not changed.

## Limitations

- If a server provides no ETag or Last-Modified, same-length replacement on the same URL cannot be detected from HTTP metadata alone. The client still enforces total length and source identity but cannot prove byte identity across requests.
- No Drive URL resolution, deployment parsing, progress callback, or overall transfer orchestration is included.
- The module is available by source path but is not added to the package's public export map; doing so changes a shared manifest and needs coordinator integration.
