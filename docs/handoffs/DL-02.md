## Implementation

Added `HttpRangeClient` for inclusive byte ranges. It requires `206 Partial Content`, an exact `Content-Range`, a numeric `Content-Length` equal to the requested size, and an actual body of that size. It rejects servers that ignore Range without switching to a full download. The first valid response pins total length, ETag, and Last-Modified; later requests send `If-Range` when a strong ETag or Last-Modified is available and reject validator or length changes. A `200` after a pinned conditional request is reported as a remote resource change.

Transport failures and retryable HTTP statuses (408, 429, and 5xx) retry up to the configured attempt count. Abort stops the transfer and retry wait. Protocol errors, unsupported Range responses, and resource changes fail immediately. `HttpRangeClient.reset()` releases its pinned snapshot for a new transfer. The module entrypoint is `packages/core/src/download/http/index.ts`; package-level exports were not changed.

## Limitations

- If a server provides no ETag or Last-Modified, same-length replacement cannot be detected from HTTP metadata alone. The client still enforces the total length but cannot prove byte identity across requests.
- No Drive URL resolution, deployment parsing, progress callback, or overall transfer orchestration is included.
- The module is available by source path but is not added to the package's public export map; doing so changes a shared manifest and needs coordinator integration.
