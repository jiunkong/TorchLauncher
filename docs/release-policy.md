# 배포·서명·업데이트 정책 (RELEASE-01/02 기준)

2026-10-22 사용자 결정과 미결정 항목을 기록한다. 구현 전 기준 문서이며, 결정 변경은 사용자 승인 후 이 문서와 `docs/progress.md`를 함께 갱신한다.

## 확정된 결정

### 1. 런처 프로그램(공통 런처) 업데이트: 앱이 확인하고 사용자 동의 후 교체
- 런처는 시작할 때 공식 배포 위치에서 새 버전을 확인하고, 사용자가 동의하면 내려받아 스스로 교체한다. 운영자가 런처를 다시 내보내 전달할 필요가 없다.
- 서버 데이터(`<userData>/servers/<서버 ID>`)는 런처 실행 파일과 분리되어 있으므로 교체해도 보존된다.
- Windows 포터블 exe는 실행 중인 파일을 덮어쓸 수 없다. 새 파일을 내려받아 검증한 뒤 종료 후 교체하는 보조 절차가 필요하다. **electron-updater가 portable 대상을 지원하는지는 아직 확인하지 못했다(검색 결과 불충분).** 구현 전에 공식 문서로 확인하고, 지원하지 않으면 자체 교체 절차를 설계한다.
- 업데이트 파일은 우리가 서명한 매니페스트(버전, 해시, 길이, 서명)로 검증한다. 코드 서명(Authenticode) 여부와 무관하게 이 검증이 업데이트 무결성의 기준이다. HTTPS만 믿지 않는다.
- 업데이트로 받은 파일은 앱이 직접 내려받으므로 Windows의 인터넷에서 받은 파일 표시(Mark of the Web)가 붙지 않는다. SmartScreen 경고는 사용자가 ZIP을 받아 처음 실행할 때 한 번만 해당한다.
- 서버 설정 파일에 **최소 런처 버전**을 넣어, Studio가 새 기능을 쓰면 그보다 낮은 런처는 업데이트를 안내한다.

### 2. 배포 파일(torchpack) 신뢰: 운영자 서명 검증 + 롤백 방지
- 위협: 배포 링크(예: Drive)가 탈취되면 악성 모드를 모든 플레이어에게 배포할 수 있다. 현재 해시는 손상 검사일 뿐이다.
- 방식(초안, 구현 배정 시 상세 확정): Studio가 프로젝트마다 서명 키(Ed25519 후보)를 만들고 배포 파일 인덱스에 서명한다. 서버 설정(JSON)에 공개키를 넣어 런처가 검증한다. 서명이 없거나 틀리면 동기화를 거부한다.
- 롤백 방지: 배포마다 증가하는 번호(또는 시각)를 인덱스에 넣고, 런처는 지금까지 본 값보다 낮은 배포를 거부한다.
- 운영자 부담: 개인 키를 안전하게 보관해야 한다. 키를 잃으면 새 키로 런처를 다시 내보내 전달해야 한다. Studio는 키 백업을 안내한다.
- 기존 v1 배포 형식과 호환 방안(서명 없는 v1 거부 여부, 전환 기간)은 구현 배정 때 정한다.

### 3. 공식 런처 배포 위치: GitHub Releases
- 업데이트 확인과 Studio의 런처 내려받기는 GitHub Releases를 사용한다. 버전별 파일과 서명된 매니페스트, 체크섬을 함께 올린다.
- 저장소 공개 여부와 계정 의존은 배포 시점에 확정한다. 위치는 설정으로 분리해 나중에 바꿀 수 있게 한다.

### 4. Windows 코드 서명: 서명하지 않는다 (사용자 결정 2026-10-22)
- 비용 문제로 코드 서명(Authenticode)을 하지 않는다. 첫 실행에서 SmartScreen 경고("추가 정보 → 실행")가 뜰 수 있으며, 이를 사용자 안내와 문서에 명시한다.
- 확인한 선택지와 제외 사유(재검토용 기록):
  - 일반 코드 서명 인증서(OV/EV): 연 비용이 크고 하드웨어 토큰 등 요건이 있다. 정확한 가격은 확인하지 못했다.
  - Azure Artifact Signing(구 Trusted Signing): 월 약 $9.99이나 개인은 미국·캐나다, 조직은 미국·캐나다·EU·영국만 가입 가능(Microsoft 문서, 2026-10 확인). 한국 개인은 대상이 아닐 가능성이 높다.
  - 오픈소스 무료 서명(SignPath Foundation 등): 사용자가 확인한 바로는 악용 위험으로 더 이상 제공되지 않는 것으로 보인다(#0은 직접 확인하지 못했다).
- 업데이트·배포 무결성은 위 1, 2번의 자체 서명 검증이 보장하므로 Authenticode 없이도 유지된다. 업데이트로 받은 파일에는 인터넷 표시(Mark of the Web)가 붙지 않아 경고는 ZIP에서 처음 실행할 때 한 번이다.
- 설정을 실행 파일 안에 넣는 재패키징은 하지 않는다(서버 설정은 옆 JSON 파일). 앱 아이콘 변경도 exe 파일 자체가 아니라 실행 중 창에만 적용한다.
- 재검토 조건: 출시 직전, 조직 설립 또는 해외 가입이 가능해졌을 때, 경고로 인한 이탈이 문제로 확인될 때.
